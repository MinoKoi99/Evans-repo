## 二、9 个坑的完整记录

### 坑 1：`shell: bash` 隐式带 `-e`

**症状**：CI 里 step 直接失败，日志显示脚本在某个「预期会失败」的命令后就停了，后面的断言一行都没跑。

**原因**：

```yaml
- run: |
    set -uo pipefail          # 你以为只开了 -u 和 pipefail
    check "flow style" fail   # 这里 node 返回 1（按设计拒绝清理）
    echo "后面的断言"          # 永远执行不到
```

但 GitHub Actions 的 `shell: bash` 实际执行的是：

```
bash --noprofile --norc -e -o pipefail {0}
```

**`-e` 一直有效**，不因为你写了 `set -uo pipefail` 而关闭。

**修法**：

```bash
set +e
node script.cjs          # 预期会失败的调用
RC=$?
set -e
```

**注意**：`clean-all.sh` 这类被 `bash "$script"` 调用的脚本，因为它自己没开 `-e`，所以内部不受影响。**只有 CI 的 `run:` 块和它直接调用的顶层脚本受影响。**

### 坑 2：`md5sum | cut` 的退出码是 `cut` 的

**症状**：macOS 上哈希恒为空，前后比较永远相等，断言形同虚设。

**原因**：

```bash
B=$(md5sum "$f" 2>/dev/null | cut -d' ' -f1 || md5 -q "$f")
#    ↑ 失败                  ↑ 成功（exit 0）
#                            ↓ || 不触发，B 得到空字符串
```

管道退出码取**最后一个命令**（`cut`）的。`md5sum` 失败但 `cut` 成功，所以 `||` 不会兜底。

**修法**：写一个跨平台哈希函数，**不要在管道里兜底**。

```bash
hash_file() {
  if command -v sha256sum >/dev/null 2>&1; then sha256sum "$1" 2>/dev/null | cut -d' ' -f1
  elif command -v shasum >/dev/null 2>&1;  then shasum -a 256 "$1" 2>/dev/null | cut -d' ' -f1
  elif command -v md5 >/dev/null 2>&1;     then md5 -q "$1" 2>/dev/null
  else md5sum "$1" 2>/dev/null | cut -d' ' -f1; fi
}
```

### 坑 3：Git Bash 的 `ps` 不支持 `-eo`

**症状**：Windows 上进程列表为空，所有进程都识别不到。

**原因**：`list-dsh-procs.sh` 原本用 `ps -eo pid=,command=` 取进程，macOS/Linux 支持，**Git Bash 的 `ps` 是简化版，不支持 `-eo`**。

**修法**：Windows 走独立 PowerShell 脚本，不要内联。

```bash
is_windows() {
  case "$(uname -s 2>/dev/null)" in MINGW*|MSYS*|CYGWIN*) return 0 ;; esac
  return 1
}

emit_procs() {
  if is_windows; then
    powershell -NoProfile -ExecutionPolicy Bypass -File "$WPS1" 2>&1
  else
    ps -eo pid=,command= 2>/dev/null | sed -n 's/^ *\([0-9][0-9]*\) */\1|other|/p'
  fi
}
```

**为什么不要内联**：`powershell -Command "..."` 里的多层引号会被 Git Bash 吃掉，导致语法错。写成 `.ps1` 文件用 `-File` 调用最稳。

### 坑 4：`$!` 在 Git Bash 上是 wrapper PID

**症状**：测试用 `A=$!` 记 PID，再用它去匹配 `detect-dsh-procs.ps1` 的输出，**永远匹配不上**——但两个进程明明都在。

**原因**：

```bash
node script.js &       # Git Bash 启动了一个 wrapper
A=$!                   # ← 拿到 wrapper 的 PID
```

而 `Get-CimInstance -Filter "Name='node.exe'"` 拿到的是**真实 node.exe 的 PID**。两者不是同一个数。

**修法**：不依赖 `$!`，从输出里按测试路径反查。

```bash
OUT=$(bash scripts/list-dsh-procs.sh 2>&1)

find_pid() {
  local hit
  hit="$(printf '%s\n' "$OUT" | grep -F "$1" 2>/dev/null | head -1)" || true
  [ -z "$hit" ] && { printf ''; return 0; }
  printf '%s\n' "$hit" | sed -n 's/.*PID=\([0-9][0-9]*\).*/\1/p' || true
  return 0
}
A="$(find_pid 'deepseek-tools/unrelated.js')" || true
B="$(find_pid '@deepseek-ai/dsh/lib/bin.js')" || true
```

**注意 `|| true` 和 `return 0`**：见坑 6。

### 坑 5：`pkill -f "$路径"` 会匹配到自己

**症状**：本地测试卡死 600 秒，没有任何输出。

**原因**：

```bash
pkill -9 -f "$PT/"     # 执行这条命令的 bash 命令行里也含 $PT/
                       # → 杀掉自己 → trap 触发 → 再 pkill → 死循环
```

**修法**：

- **不要用 `pkill -f` 做兜底**，只用反查到的 PID
- 如果必须留 `trap`，加防重入标志

```bash
CLEANED=0
cleanup() {
  [ "$CLEANED" = "1" ] && return 0
  CLEANED=1
  for pid in "$A" "$B"; do [ -n "$pid" ] && kill -9 "$pid" 2>/dev/null; done
  return 0
}
trap 'cleanup' EXIT
```

### 坑 6：`grep` 失败 + `pipefail` + `-e` = 脚本在打印诊断前退出

**症状**：CI 日志里连诊断行都没打印出来，直接 `Process completed with exit code 1`。

**原因**：

```bash
A=$(find_pid 'xxx')
#   ↑ find_pid 内部：printf | grep -F | head -1 | sed
#   ↑ grep 找不到 → 返回 1
#   ↑ set -o pipefail → 整个管道返回 1
#   ↑ $(...) 失败
#   ↑ -e → 脚本立即退出
```

**这个坑最坑的地方**：我为了排查加诊断，结果诊断本身也没跑出来，看起来像「诊断没生效」，实际是「脚本在诊断之前就死了」。

**修法**：

```bash
find_pid() {
  local hit
  hit="$(printf '%s\n' "$OUT" | grep -F "$1" 2>/dev/null | head -1)" || true   # ← 吞掉退出码
  [ -z "$hit" ] && { printf ''; return 0; }
  printf '%s\n' "$hit" | sed -n 's/.*PID=\([0-9][0-9]*\).*/\1/p' || true
  return 0                                                                     # ← 显式成功
}
A="$(find_pid 'xxx')" || true                                                  # ← 双重保险
```

整段断言密集的测试，可以在开头 `set +e`。

### 坑 7：PowerShell `-File` 收到 Git Bash 的 Unix 路径

**症状**：`list-dsh-procs.sh` 输出只有 3 行，**连 `QUERY_FAIL` 都没有**——脚本看起来像没跑。

**原因**：

```
Git Bash:  SCRIPT_DIR = /d/a/Evans-repo/Evans-repo/scripts
PowerShell: -File /d/a/.../detect-dsh-procs.ps1    ← 不认这种路径
```

而 `2>/dev/null` 把 PowerShell 的报错吞了，所以只看到空白。

**修法**：

```bash
local WPS1="$ps1"
if command -v cygpath >/dev/null 2>&1; then
  WPS1="$(cygpath -w "$ps1" 2>/dev/null)" || WPS1="$ps1"
fi
"$SELF" -NoProfile -ExecutionPolicy Bypass -File "$WPS1" 2>&1   # ← 不要 2>/dev/null
```

### 坑 8：`.ps1` 无 BOM，PS 5.1 按 ANSI 读

**症状**：

```
QUERY_FAIL PowerShell 退出码 1:
At D:\a\...\detect-dsh-procs.ps1:55 char:32
+         Write-Output ("{0}
```

**第 55 行看起来完全正常**，本地 `pwsh 7` 解析也 OK。

**原因**：

- 文件是 **UTF-8 无 BOM**
- CI 的 `powershell` 是 **Windows PowerShell 5.1**
- 5.1 读无 BOM 的 UTF-8 时按 **ANSI(CP936)** 解码
- → 中文注释变乱码 → **引号配对错乱** → 语法错误

**本地 `pwsh 7` 默认 UTF-8，所以测不出来。**

**修法**：

```bash
# 检查
xxd -l 3 -p script.ps1      # 应该是 efbbbf

# 加 BOM
printf '\xef\xbb\xbf' | cat - script.ps1 > tmp && mv tmp script.ps1

# 或者在 python 里
# p.write_bytes(b'\xef\xbb\xbf' + p.read_bytes())
```

**再加一层保险**：调用时优先 `pwsh`（7.x 默认 UTF-8），回退 `powershell`。

```bash
WPS1="$(cygpath -w /path/to/detect-dsh-procs.ps1)"
for SELF in pwsh powershell powershell.exe; do
  if command -v "$SELF" >/dev/null 2>&1; then
    "$SELF" -NoProfile -ExecutionPolicy Bypass -File "$WPS1"
    break
  fi
done
```

### 坑 9：`clean-all.sh` 传给 node 的路径是 Unix 风格

**症状**：

```
==> 3.5) 预检清理操作
     cordis.patch.yml: 预检通过（会移除 1 个条目）
  ✗ package.json 解析失败
ERR 预检失败，未删除任何文件、未改动任何配置。
```

**这是唯一一个影响终端用户的 bug**（其余 8 个都是测试环境问题）。

**原因**：

```bash
node -e "JSON.parse(fs.readFileSync('/tmp/tmp.xxx/profiles/web/package.json'))"
```

Windows 原生 node 不认 Git Bash 的 `/tmp/xxx`。

**修法**：区分「给 bash 用的路径」和「给 node 用的路径」。

```bash
DSH="${DSH_HOME:-$HOME/.dsh}"     # bash 文件操作
DSH_NODE="$DSH"                    # 传给 node
case "$(uname -s 2>/dev/null)" in
  MINGW*|MSYS*|CYGWIN*)
    command -v cygpath >/dev/null 2>&1 && \
      DSH_NODE="$(cygpath -w "$DSH" 2>/dev/null)" || DSH_NODE="$DSH"
    [ -z "$DSH_NODE" ] && DSH_NODE="$DSH"
    ;;
esac
```

然后把**所有** node 调用的入参换成 `$DSH_NODE`。

**路径转换只在这一个边界做**：Git Bash → 原生 Windows 程序。macOS/Linux 分支不做任何转换。

## 三、排查方法论

### 原则 1：让错误原样透出

```bash
# ❌ 错误被吞，排查时一片空白
command 2>/dev/null
head -40 file | sed 's/^/  /'        # 文件为空时什么都不显示

# ✅ 错误可见
OUT="$(command 2>&1)"; RC=$?
echo "退出码: $RC"
echo "输出: $OUT"
```

**实测教训**：我曾经加了 6 项诊断，全部用 `head | sed`，结果文件是空的 → 诊断输出空白 → 看起来像「诊断没生效」→ 又浪费一轮。

### 原则 2：猜不出来就上 `bash -x`

```bash
bash -x script.sh 2>&1 | head -60
```

**`bash -x` 一次性暴露了「`✗ package.json 解析失败`」，抵得上之前 4 轮往返。**

### 原则 3：本地复现 CI 的 `run:` 块

```bash
ruby -ryaml -e '
d = YAML.load_file(".github/workflows/e2e.yml")
d["jobs"]["<job名>"]["steps"].each do |s|
  if s["name"] == "<step名>"
    File.write("/tmp/step.sh", s["run"])
  end
end
'
bash -e /tmp/step.sh
```

### 原则 4：本地验证必须用 CI 的方式

```bash
bash script.sh          # ❌ 漏掉 -e -o pipefail
bash -e script.sh       # ✅
```

## 四、这次故障的时间线（教训）

| 轮次 | 改了什么 | 结果 | 判断是否正确 |
|---|---|---|---|
| 1 | 首次接入 CI | 6 项失败 | — |
| 2 | 猜「hash 问题」 | 6 项失败 | ❌ 猜错方向 |
| 3 | Windows `ps` / `chmod` | 被取消 | — |
| 4 | 找到 `-e` 问题 | 4 项失败 | ✅ macOS 转绿 |
| 5 | T4 诊断 | 2 项失败 | ✅ |
| 6 | `bash -x` | 定位到 `package.json 解析失败` | ✅ **关键** |
| 7 | `DSH_NODE` + 反查 PID | **全绿** | ✅ |

**第 2 轮和第 6 轮的对比**：都是「加诊断」，但第 2 轮在**猜**，第 6 轮用 `bash -x` 让脚本**自己说**。

**结论：`bash -x` 应该在第一次 CI 失败时就用，不是第 6 轮。**

## 五、可复用的模板

### 跨平台脚本骨架

```bash
#!/usr/bin/env bash
set -uo pipefail

SCRIPT_DIR="$(cd "$(dirname "${BASH_SOURCE[0]:-$0}")" && pwd)"

is_windows() {
  case "$(uname -s 2>/dev/null)" in MINGW*|MSYS*|CYGWIN*) return 0 ;; esac
  return 1
}

hash_file() {
  if command -v sha256sum >/dev/null 2>&1; then sha256sum "$1" 2>/dev/null | cut -d' ' -f1
  elif command -v shasum >/dev/null 2>&1;  then shasum -a 256 "$1" 2>/dev/null | cut -d' ' -f1
  elif command -v md5 >/dev/null 2>&1;     then md5 -q "$1" 2>/dev/null
  else md5sum "$1" 2>/dev/null | cut -d' ' -f1; fi
}

# 给 bash 的路径 和 给原生程序的路径 分开
HOME_FOR_BASH="/tmp/xxx"
HOME_FOR_NODE="$HOME_FOR_BASH"
if is_windows && command -v cygpath >/dev/null 2>&1; then
  HOME_FOR_NODE="$(cygpath -w "$HOME_FOR_BASH" 2>/dev/null)" || HOME_FOR_NODE="$HOME_FOR_BASH"
fi
```

### Windows 进程查询（`.ps1` 独立文件，带 BOM）

```powershell
# 文件必须 UTF-8 with BOM
param([switch]$Kill)

$procs = Get-CimInstance Win32_Process -Filter "Name='node.exe'" -ErrorAction SilentlyContinue
if ($null -eq $procs) { Write-Output "QUERY_FAIL|Get-CimInstance 返回 null"; exit 2 }

foreach ($p in $procs) {
    $cmd = $p.CommandLine
    if ([string]::IsNullOrWhiteSpace($cmd)) { continue }
    Write-Output ("{0}|{1}" -f $p.ProcessId, $cmd)
}
```

### CI step 骨架

```yaml
- name: <步骤名>
  shell: bash
  run: |
    set -uo pipefail
    hash_file() { ... }

    # 预期会失败的调用
    set +e
    <命令>
    RC=$?
    set -e

    # 断言：用 if，不用 &&
    if [ "$RC" != "0" ]; then
      echo "OK  正确拒绝"; P=$((P+1))
    else
      echo "FAIL 不该通过"; F=$((F+1))
    fi

    if [ "$F" -gt 0 ]; then exit 1; fi
    exit 0
```
